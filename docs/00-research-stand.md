# Стенд-соревнование по компьютерному зрению для неподготовленной аудитории

Статус: **ресерч завершён, ключевая связка проверена на железе.** Стенда пока нет.
Документ отвечает на вопросы: реально ли, на какой платформе, на какой задаче и данных, чем считать.

Привязка: доклад [«Анализ изображений: методы и промышленные применения»](../../sfu-presentation/docs/доклад-анализ-изображений.md). Аудитория стенда та же — учёные и прикладные специалисты, не из компьютерного зрения и не программисты.

---

## 1. Вердикт: реально

Ни одна часть стенда не требует разработки с нуля. Собирается из готового:

| Часть | Чем закрывается | Риск |
|---|---|---|
| Ноутбук в браузере | готовая платформа | средний — см. §2 |
| Детекция / сегментация / трекинг / глубина | **готовые веса, только инференс** | низкий |
| Лидерборд с автоскорингом | штатная функция платформы | средний |
| Эталон для метрик | родная разметка набора | низкий |
| Картинки, графики, разбор ошибок | matplotlib в ноутбуке | низкий |

**Главная находка ресерча: обучать не нужно ничего.**

Фундаментальные модели закрывают все четыре ступени без единой эпохи обучения: детектор с открытым словарём принимает текстовый запрос, сегментатор работает по клику или рамке, трекинг получается памятью по кадрам, глубина берётся монокулярной моделью. Участник **настраивает**, а не обучает, и каждая итерация занимает секунды вместо минут.

Это меняет и формат: стенд — это один или несколько ноутбуков, где человек прожимает ячейки, а на выходе получает визуализации, графики и позицию в лидерборде.

**Плата за это — GPU.** Ранний вывод про «всё считается на CPU» снят: тяжёлые сегментаторы дают порядка секунды на кадр на RTX 3090, на процессоре это десятки секунд. Площадка обязана давать ускоритель — подробности в §7.6.

## 2. Платформа: главный риск лежит не в ML

Критерий, заданный заказчиком, — **минимальный безболезненный вход участника**.

### 2.1. Kaggle — отпадает

Формально подходит идеально: Community Competitions бесплатны, есть публичный и приватный лидерборд, ноутбуки с T4. Но вход из РФ:

- нужен VPN,
- почта не из домена `.ru`, иначе регистрация падает с ошибкой,
- верификация номера телефона для GPU и интернета в ноутбуке — лотерея.

Для тридцати человек, далёких от программирования, это стоп-фактор: половина аудитории застрянет на регистрации и до задачи не дойдёт. **Не рассматриваем.**

### 2.2. Codenrock — рекомендация

Российская платформа, позиционируется как аналог Kaggle. По найденным материалам:

- **бесплатна для учебных заведений** (отдельно объявлено);
- ML-соревнования с автоскорингом, **публичный лидерборд по открытой части и приватный по скрытой** — ровно та механика, что нужна;
- **Jupyter Notebook прямо в браузере**, при проверке решений инференс на сервере с GPU (T4 / A100);
- вход участника — обычная регистрация, без VPN и без не-.ru почты;
- 100k+ пользователей, есть API и интеграция с GitLab.

**Что проверить лично до решения** (сайт не отдаётся из-за рубежа, всё выше — по вторичным источникам):

1. процедура и сроки получения бесплатного доступа для вуза;
2. квота: сколько участников одновременно, ограничение на число сабмитов в день;
3. можно ли залить свой стартовый ноутбук так, чтобы участник открыл его в один клик;
4. можно ли положить свой датасет и свой скоринг-скрипт;
5. закрытое соревнование по коду приглашения или только публичное.

### 2.3. Запасные варианты

| Вариант | Вход участника | Лидерборд | Ноутбук | Комментарий |
|---|---|---|---|---|
| ODS.ai | аккаунт, РФ | есть | своей среды нет | лидерборд без среды исполнения |
| All Cups (VK) | аккаунт, РФ | есть | поддержка ML-задач | ориентирован на крупные чемпионаты |
| Yandex DataSphere | Yandex ID + **биллинг облака** | нет | есть, гранты на обучение | биллинг — лишний барьер; лидерборда нет |
| Google Colab | Google-аккаунт, местами VPN | нет | есть | только как запасная среда |
| HF Space (Gradio) + Colab | HF-аккаунт | самодельный, ~100 строк | внешний | «лёгкий self-host» без своего сервера |
| Свой JupyterHub + FastAPI | ссылка и код, барьера нет | свой | свой | минимум трения для участника, максимум для организатора |

**Развилка, если Codenrock не подойдёт:** лидерборд как Space на Hugging Face (приём CSV, таблица результатов) плюс ноутбук в DataSphere или Colab. Это и есть «поднять у себя», но без своего хоста — хостинг чужой и бесплатный.

Отдельно проверено и отброшено: **JupyterLite на GitHub Pages** даёт ноль аккаунтов и ноль сервера, но в Pyodide нет torch. Годится только для варианта «организатор заранее посчитал эмбеддинги, участник обучает логрегрессию» — детекции, сегментации и трекинга там не будет.

## 3. Задача: лестница из четырёх ступеней, настройка вместо обучения

Требование — показать весь цикл: детекция, сегментация, трекинг, глубина. Обучить четыре модели за полтора часа нельзя, но этого и не требуется: все четыре ступени закрываются готовыми моделями, а участник их **настраивает**.

Это не упрощение ради экономии времени. Так задача и решается сегодня, и ровно об этом §17 доклада: основу берут готовой, собственная разметка нужна в объёме десятков снимков, а не десятков тысяч.

### 3.1. Четыре ступени

Повторяют лестницу из §1 доклада, поэтому стенд ложится на текст без швов.

| Ступень | Вопрос к картинке | Что крутит участник | Что видит |
|---|---|---|---|
| 1. Детекция | что и где | **текст запроса**, порог уверенности | рамки и оценки; объекты пропадают и появляются при движении порога |
| 2. Сегментация | какой контур, какая площадь | вид промпта, порог | маски, площадь каждого объекта |
| 3. Трекинг | тот же ли это объект | параметры трекера, минимальная длина трека | номера над объектами, подсчёт потока |
| 4. Глубина | как далеко | ничего — сравнение | карта расстояний против измерения лидаром |

### 3.2. Лидерборд

Метрика на каждой ступени считается против **родной разметки набора** — размечать руками ничего не нужно.

Итерация занимает секунды, поэтому за сессию человек делает десятки попыток. Это принципиально: обучение с его минутами ожидания убивает темп, а настройка его держит.

Ручки: текст запроса · порог уверенности · порог удаления дублей · параметры трекера · минимальная длина трека · положение линии счёта.

Ценность именно такого лидерборда:

- **метрика деловая, а не абстрактная**: не mAP, а «система насчитала 47 объектов, реально 51»;
- он воспроизводит §12 доклада — выбор границы принятия решения есть решение управленческое, а не техническое: подняли порог, пропустили объекты; опустили, насчитали лишних;
- он воспроизводит §9 — в докладе четырнадцать номеров пришлось на девять реальных линий. Участник получит эту ошибку своими руками и сам поймёт, почему она лечится правилом, а не заменой модели;
- **главная ручка — слова** (§7.5). Человек, далёкий от программирования, крутит формулировку запроса, а не код, и за три попытки понимает, что модель отвечает на вопрос, а не «знает объект».

## 4. Обзор кейсов на платформах

Решение заказчика: **только открытые данные**, своих производственных материалов не берём. Искали готовый кейс, который закрывает все ступени сразу, — чтобы не собирать сцену из кусков.

**Лицензия из критериев отбора исключена** по решению заказчика. Значение имеют две вещи: данные открыты и данные реально скачиваются без мучений. Тип лицензии в таблицах ниже оставлен как справка, на вердикт он не влияет. Ограничения на распространение при этом остаются фактом, который учитывается при перевыкладке данных на площадку, — но выбор сцены больше не определяют.

### 4.1. Kaggle: промышленные соревнования

| Соревнование | Год | Сцена | Что даёт | Пригодность |
|---|---|---|---|---|
| **Severstal: Steel Defect Detection** | 2019 | **движущаяся стальная полоса**, съёмка высокочастотными камерами | 12 568 обучающих кадров 1600×256, 4 класса дефектов, маски в RLE | **★ ядро стенда** |
| TensorFlow — Help Protect the Great Barrier Reef | 2021 | подводное видео | рамки покадрово, **есть `video_id` / `sequence` / `frame`** | ★ единственный с честными видеопоследовательностями, но не промышленный |
| Sartorius — Cell Instance Segmentation | 2021 | микроскопия | instance-маски касающихся клеток, 3 типа | ○ прямо ложится на §8, но сцена научная |

### 4.3. Флотация: проверено, отпадает

Направление живое: «Норникель» внедрил видеоаналитику пены на Талнахской обогатительной фабрике, виртуальный датчик считает число, размер и скорость движения пузырьков. ODS публиковал разбор задачи — трекинг множества объектов без разметки.

**Но открытого датасета нет.** В том разборе для трекинга было размечено *30 секунд видео*, и в открытый доступ материалы не выкладывались; тестирование шло на десяти роликах по три секунды. Заводские данные закрыты.

Как соревнование не годится. Как сюжет в докладе — да: «вот задача, вот почему разметка тут не масштабируется, вот как её обходят».

### 4.4. Российские платформы

Codenrock, ODS и All Cups регулярно проводят ML-турниры на промышленных кейсах, но **данные закрываются после окончания соревнования**. Взять готовый набор оттуда нельзя, только провести своё.

## 5. Рекомендация по данным

Требование сузилось: нужны **детекция, сегментация, трекинг**. Ступень «учим норму» (поиск аномалий) снята.

### 5.1. Severstal: две ступени из трёх

| Ступень | Что даёт Severstal | Честность |
|---|---|---|
| Сегментация | маски RLE, 4 класса дефектов | **родная разметка** |
| Детекция | рамка вокруг связной области маски | выводится из масок, стандартная практика |
| Трекинг | **нечего взять** | последовательностей нет |

Проблема конкретна: имена файлов — хеши, порядок кадров не восстанавливается, номеров объектов во времени нет. Единственный доступный ход — **«прокатка»**: окно 256×256 едет вдоль кадра 1600×256, дефект въезжает и выезжает из поля зрения. Постановка честная (это и есть линейный контроль проката), но **данных трекинга в наборе нет** — эталонный счёт пришлось бы проставлять руками, и проверять качество сопоставления объектов между кадрами будет не с чем.

Вывод: Severstal хорош там, где нужна обучаемая ступень с промышленной сценой и настоящими масками. Ядром для трёх ступеней сразу он быть не может.

### 5.2. KITTI-MOTS: все три ступени настоящей разметкой

Единственный открытый набор в обзоре, где **детекция, сегментация и трекинг закрыты одной родной разметкой**.

| Свойство | Значение |
|---|---|
| Сцена | городская езда, съёмка с движущейся платформы |
| Объём разметки | 21 обучающая последовательность + 29 тестовых |
| Классы | автомобиль, пешеход |
| Формат | однослойные PNG, **у каждого экземпляра свой номер**, сохраняемый по кадрам |
| Что отсюда берётся | маски → сегментация · рамки из масок → детекция · номера по кадрам → **трекинг с эталоном** |

Три причины, почему это лучший вариант под новое требование:

**Эталон трекинга родной.** Не нужно считать вручную: номера объектов проставлены по кадрам, и качество сопоставления проверяется автоматически. Метрика лидерборда получается честной — например, число уникальных объектов, прошедших через кадр, сверяется с разметкой.

**Обучать не обязательно.** Автомобиль и пешеход входят в набор классов COCO, поэтому предобученный YOLO-seg работает на этой сцене из коробки. Соревнование сводится к **настройке** — порог уверенности, порог удаления дублей, параметры трекера, минимальная длина трека. Итерация занимает секунды, за сессию человек делает десятки попыток. Это ровно §12 доклада: выбор границы принятия решения есть управленческое решение.

**Вау сохраняется.** Городская езда с движущейся платформы — это и есть визуальный язык автономного транспорта, ради которого рассматривались Waymo и Lyft. Только весит на три порядка меньше и не требует согласования от лица организации.

*Проверить перед стартом: точный объём и требуется ли регистрация — исходные кадры лежат на стороне KITTI, разметка MOTS отдельным небольшим архивом.*

### 5.3. Если KITTI окажется неудобен

**DAVIS 2017, 480p.** Шестьдесят обучающих и тридцать проверочных роликов, маски экземпляров с постоянными номерами по кадрам, **прямая ссылка на zip без регистрации**, вес небольшой. Сегментация и трекинг закрыты полностью. Слабое место — классов нет, поэтому детекция как «что и где» вырождается в «где».

**YouTube-VIS 2021.** 3859 роликов, 232 тысячи масок, 8171 экземпляр, классы есть — то есть все три ступени с классами. Тяжелее KITTI-MOTS.

**OVIS.** 901 ролик, объекты дольше и сильнее перекрываются. Как раз тот случай, где трекинг ломается на перекрытиях — прямая иллюстрация §9. Как основа тяжеловат, как отдельный сложный этап хорош.

### 5.4. Глубина: четвёртая ступень, и она сильнее прочих

KITTI даёт не только MOTS, но и **официальный набор глубины**: свыше 93 000 карт, выровненных с исходными кадрами, в формате uint16 PNG. Эталон получен накоплением облаков точек Velodyne HDL-64 с проверкой по стереопаре. Разрешение то же, 1242×375.

Отсюда получается ступень, которой нет ни у одного промышленного набора:

| Что показываем | Как |
|---|---|
| Предсказанная глубина | монокулярная модель (Depth Anything v2) по одному обычному снимку |
| Измеренная глубина | карта из лидара, спроецированная в тот же кадр |
| **Сравнение** | ошибка предсказания в метрах, по зонам кадра |

Метрика лидерборда читается вообще без подготовки: «модель сказала 12 метров, лидар говорит 14,3». И это ровно два тезиса доклада сразу — §14 о камере как измерительном приборе и §19 о том, что точность выше точности эталона проверить нечем.

Плюс тот же участник может подставить **свою** фотографию и получить по ней карту глубины — уже без эталона, но с полным ощущением, что инструмент у него в руках.

### 5.5. Итоговая связка

Одна сцена — городская езда. Один источник — KITTI. Четыре ступени, все с настоящим эталоном, формат PNG и текст, никакого TFRecord.

| Ступень | Данные | Эталон | Что делает участник |
|---|---|---|---|
| Детекция | KITTI-MOTS | рамки из масок | крутит порог уверенности |
| Сегментация | KITTI-MOTS | маски экземпляров | смотрит контуры, считает площади |
| Трекинг | KITTI-MOTS | **номера по кадрам** | крутит параметры трекера, считает уникальные объекты |
| Глубина | KITTI Depth | **карты из лидара** | сравнивает предсказание с измерением |

Обучать при этом ничего не обязательно: автомобиль и пешеход входят в классы COCO, монокулярная глубина берётся готовой. Соревнование сводится к настройке, итерация занимает секунды, а эталон на всех четырёх ступенях родной.

**Опционально:** Severstal вторым блоком, если важно, чтобы человек своими руками обучил модель на промышленной сцене, а не только настроил чужую. Две-три минуты обучения, промышленные маски, свой лидерборд.

**Опционально:** nuScenes-mini, если захочется мультикамерности и кругового лидара — 10 сцен одним архивом, чистый Python-devkit.

## 6. Вау-эффект: чем за него платить

Запрос: взять что-то уровня Waymo / Lyft Prediction, автономный транспорт или роботов.

### 6.1. У Waymo два разных набора, и путать их нельзя

**Waymo Open Motion** — траектории агентов, задача motion prediction, метрики ADE / FDE. Изображений в постановке практически нет. Именно этот набор непригоден для стенда: непонятная неспециалисту постановка при огромном весе. То же относится к Lyft L5 (1000+ часов, 17 000 сцен по 25 секунд).

**Waymo Open Perception — это другое, и там есть всё, что нужно:**

| Что | Сколько |
|---|---|
| Сегменты | 1950 штук по 20 секунд, съёмка 10 Гц, ~390 000 кадров |
| Камеры и лидары | 5 камер, 1 дальний лидар, 4 ближних; синхронизация, калибровка, **проекции лидара на камеры** |
| Рамки на камерах | **11,8 млн 2D-рамок с номерами треков**, 1000 сегментов |
| Рамки на лидаре | **12,6 млн 3D-рамок с номерами треков**, 1200 сегментов |
| Сегментация | **3D-разметка на 23 класса**, 1150 сегментов |
| Классы | транспорт, пешеходы, велосипедисты, знаки |

То есть детекция, сегментация, трекинг и глубина закрыты одним набором и настоящей разметкой. Возражение по объёму снимается тоже: сегменты качаются поштучно, двух-трёх хватит на стенд.

Остаются два практических препятствия, и они не про данные:

1. **Формат.** Всё лежит в TFRecord, читается пакетом `waymo-open-dataset`, который жёстко привязан к версиям TensorFlow. Это самая хрупкая часть конструкции и главный риск для стенда, который должен просто запуститься у тридцати человек.
2. **Доступ.** Регистрация и принятие соглашения, с подтверждением полномочий от лица организации.

Формальных Challenges у Waymo в 2026 нет, живы только лидерборды.

**Вывод:** Waymo Perception по составу подходит; отказываемся от него не из-за данных, а из-за упаковки. Ту же сцену и ту же разметку дают KITTI (PNG и текстовые файлы, никакого TensorFlow) и nuScenes (чистый Python-devkit, готовая mini-подвыборка). При прочих равных выигрывает то, что заведётся с первого раза.

### 6.2. Что из этого мира берётся дёшево

**nuScenes-mini.** Десять сцен, один архив `v1.0-mini.tgz` (порядка нескольких ГБ, *уточнить точный размер*), CC BY-NC-SA 4.0, прямая ссылка на скачивание. В нём шесть камер, лидар, радар, трёхмерные рамки **с номерами треков** и карта. Штатный devkit рисует проекции облака точек на камеры и вид сверху.

Это ровно §14 доклада — камера как измерительный прибор, облако точек, развёртка. И это единственный способ получить селфдрайвинг-антураж, не влезая в терабайты.

Ограничение честное: **обучать на нём в рамках стенда нечего**. Это блок «посмотреть и покрутить», а не соревнование.

### 6.3. Где вау на самом деле сильнее

Ключевое наблюдение: красивая чужая сцена впечатляет слабее, чем собственная картинка участника, прошедшая через модель. В первом случае человек зритель, во втором — участник. А задача стенда сформулирована как «показать инструмент, а они его на себя наложат» — то есть человек должен приложить модель к своему, здесь и сейчас.

Четыре кнопки, все на готовых весах, все считаются на CPU за секунды:

| Кнопка | Что делает | Отсылка |
|---|---|---|
| **Сегментация по клику** (SAM 2) | ткни в любой объект на своей фотографии — он выделится контуром | §17 |
| **Глубина из одного снимка** (Depth Anything v2) | обычное плоское фото превращается в карту расстояний | §14 |
| **Детекция и трекинг на ролике** | рамки, номера, подсчёт прошедших объектов | §6, §9 |
| **Описание словами** (VLM) | модель называет, что видит, и обосновывает вывод | §18 |

Первые две дают самый громкий эффект, потому что человек подставляет **свою** фотографию — из телефона, с рабочего стола, со своего эксперимента — и немедленно видит результат. Дальше он сам додумывает, куда это приложить, и именно это и есть цель стенда.

### 6.4. Как это собрать вместе

Разделение ролей, повторяющее структуру доклада:

- **Соревновательное ядро** — промышленное, лёгкое, с обучением и честными числами: Severstal. Здесь лидерборд, метрики, матрица ошибок, разбор ошибок. Акты I–II доклада.
- **Вау-блок** — фундаментальные модели без обучения и без лидерборда: четыре кнопки выше плюс nuScenes-mini, если нужен именно селфдрайвинг. Акт III доклада, §17–18.

Такой стенд даёт и «я сам обучил модель и вижу себя в таблице», и «господи, оно понимает мою фотографию». Ни одно из этих ощущений по отдельности не закрывает задачу.

## 7. Waymo Open Perception: разбор

Решение по формату стенда: **обучать не обязательно.** Участник настраивает и запускает готовые модели, на выходе — визуализации, графики и метрики в лидерборде. Это снимает главное ограничение и переводит выбор данных в другую плоскость: нужен набор с богатым эталоном, а не с удобной обучающей выборкой.

### 7.1. Что внутри

| Что | Сколько |
|---|---|
| Сегменты | 2030 по 20 секунд, съёмка 10 Гц, ~390 000 кадров |
| Сенсоры | 5 камер, 1 дальний лидар, 4 ближних; синхронизация, калибровка, позы машины |
| 2D-рамки на камерах | **11,8 млн, с номерами треков**, 1000 сегментов |
| 3D-рамки на лидаре | **12,6 млн, с номерами треков**, 1200 сегментов |
| Сегментация камер | 2D паноптическая, авторазметка |
| Сегментация лидара | **23 класса**, 1150 сегментов |
| Проекции | лидар, спроецированный на камеры → **готовая карта глубины** |
| Классы | транспорт, пешеходы, велосипедисты, знаки |

### 7.2. Формат v2 снимает главное возражение

Раньше всё лежало в TFRecord и читалось пакетом `waymo-open-dataset`, привязанным к версиям TensorFlow. **В v2 это не так.**

- формат — **Apache Parquet**, колоночный;
- читается любой библиотекой, понимающей Parquet: pyarrow, pandas, dask. Ни protobuf, ни TensorFlow, ни пакета `waymo-open-dataset` не требуется;
- данные разложены **по компонентам, и качается только нужное**;
- лежит на Google Cloud Storage, можно читать потоком без полной выгрузки;
- в репозитории есть готовые тетради `tutorial_v2.ipynb` и `tutorial_camera_only.ipynb`.

Компоненты (по списку из `tutorial_v2.ipynb`): `camera_image`, `camera_box`, `camera_calibration`, `camera_hkp`, `camera_to_lidar_box_association`, `camera_segmentation`, `lidar`, `lidar_box`, `lidar_calibration`, `lidar_camera_projection`, `lidar_camera_synced_box`, `lidar_hkp`, `lidar_pose`, `projected_lidar_box`, `vehicle_pose`, `stats`.

Для стенда обязательны пять: **`camera_image`, `camera_box`, `camera_segmentation`, `camera_calibration`, `vehicle_pose`**. Файлы лежат по схеме `{bucket}/{split}/{component}/{context_name}.parquet`, бакет — `gs://waymo_open_dataset_v_2_0_0`.

**Оговорка по ступени глубины.** Она обходится дороже, чем казалось. Карта расстояний собирается из `lidar_camera_projection` **вместе с** `lidar`, а облака точек — самая тяжёлая часть набора. Если по объёму не проходим, глубина делается без эталона: монокулярная модель рисует карту, но сверять её будет не с чем. Порядок действий — в [10-waymo-download.md](10-waymo-download.md).

**Оговорка по сегментации.** Разметка положена неравномерно: в обучающем сплите это последовательности по 5 кадров (25 размеченных изображений на сегмент), в валидационном — полные прогоны на 5 Гц, 100 кадров на 5 камер, то есть 500 изображений. **Для трекинга годится только валидационный сплит.**

### 7.3. Доступ

Страницы данных закрыты входом через Google — проверено, `/open/data/perception/` перенаправляет на OAuth. Требуется принятие соглашения.

Для стенда это не барьер: **регистрируется один организатор**, скачивает подвыборку на несколько сегментов и кладёт её на площадку. Участники не регистрируют ничего — ровно тот принцип, ради которого мы отказались от Kaggle.

**Открытый вопрос номер один:** официальных размеров по сегментам и компонентам нет, вопрос об этом в трекере проекта остался без ответа. Замерять придётся самим на одном сегменте.

### 7.4. Четыре ступени без единого обучения

| Ступень | Чем делаем | Эталон из Waymo | Что крутит участник |
|---|---|---|---|
| Детекция | открытый словарь: Grounding DINO или OWLv2 — **запрос текстом** | `camera_box` | **сам текст запроса**, порог уверенности |
| Сегментация | SAM по рамке или клику | `camera_segmentation` | вид промпта, порог |
| Трекинг | SAM с памятью по кадрам либо трекер поверх детекций | **номера треков в `camera_box`** | параметры трекера, минимальная длина трека |
| Глубина | монокулярная модель по одному кадру | `lidar` + `lidar_camera_projection` | ничего — сравнение с измерением |

Эталон родной на всех четырёх ступенях. Лидерборд считается автоматически, руками ничего размечать не нужно.

### 7.5. Главная ручка стенда — слова

Открытый словарь означает, что детектор принимает текст. Значит **формулировка запроса становится гиперпараметром** — и это идеальная ручка для человека, далёкого от программирования: он крутит слова, а не код.

В вашем же проекте по дорожной разметке это уже зафиксировано: запрос `"white line on road"` дал результат чище, чем `"road line marking"`. На стенде участник пишет `pedestrian`, потом `person walking`, потом `человек`, и видит, как двигается метрика. Понимание, что модель отвечает на вопрос, а не «знает объект», приходит за три попытки.

### 7.6. Вычислительный бюджет: замерено

Здесь придётся отказаться от найденного ранее вывода про CPU.

**Замер на месте**, RTX 3090, `transformers` 5.15, SAM 3 в формате Hugging Face, bfloat16:

| Показатель | Значение |
|---|---|
| Загрузка модели | 2,9 с |
| Параметров | 860 млн |
| Прогон | 30 кадров 1280×720 за 11,8 с |
| **Скорость** | **0,39 с/кадр** |
| Результат по запросу `person` | 4 объекта, скоры 0,95–0,98, номера треков **стабильны по кадрам** |

Это лучше, чем 0,69–0,96 с/кадр из вашего проекта по дорожной разметке — там кадры были крупнее.

Следствия:

- **площадка обязана давать GPU.** Вариант «всё считается на CPU» для вау-блока отпадает окончательно;
- прогон в 30 кадров занимает 12 секунд на 3090. На T4 будет вдвое-втрое медленнее, порядка 30 секунд — темп для итерации приемлемый, но брать 200 кадров нельзя;
- веса кладутся на площадку заранее, а не качаются участником: 3,3 ГБ;
- пакет `kernels` обязателен. Без него SAM 3 молча пропускает удаление дублей, заливку дыр и чистку крапа в масках — то есть выдаёт заметно более грязный контур.

### 7.7. Одна модель закрывает три ступени

Главное, что показал замер: `postprocess_outputs` возвращает **боксы, маски и `object_ids` одним вызовом**.

| Из одного прохода | Ступень |
|---|---|
| `boxes` | детекция |
| `masks` | сегментация |
| `object_ids`, сохраняемые между кадрами | трекинг |

То есть три ступени лестницы дают не три модели, а одна, по одному текстовому запросу. Для стенда это принципиально: участник меняет **одно слово** и видит, как одновременно меняются рамки, контуры и подсчёт объектов. Ровно тот эффект, ради которого стенд затевался.

Четвёртая ступень — глубина — берётся отдельной монокулярной моделью и сверяется с проекцией лидара.

### 7.8. Waymo против KITTI

| | Waymo Perception v2 | KITTI |
|---|---|---|
| Формат | Parquet, компоненты по отдельности | PNG и текст |
| Вход | Google-логин у организатора | прямые ссылки |
| Съёмка | современная, 5 камер | 2012–2013, выглядит архивно |
| Классы | транспорт, пешеходы, велосипедисты, знаки | автомобиль, пешеход |
| Сегментация | паноптическая, авторазметка | MOTS, ручная |
| Глубина | проекции лидара | официальный набор, 93 000 карт |
| Размеры | **неизвестны, замерить** | известны |
| Вау | **выше** | ниже |

**Вывод: Waymo v2 основной, KITTI страховка.** Ставка на вау оправдывает Google-логин у одного организатора. Если замер размеров покажет, что подвыборка не влезает в площадку, или доступ окажется неудобным, — переходим на KITTI без потери структуры стенда: те же четыре ступени, тот же эталон, только сцена постарее.

### 7.9. Честная оговорка

`camera_segmentation` в Waymo — **авторазметка**, не ручная работа человека. На стенде это стоит проговорить прямо: сравнение идёт с машинным эталоном, а не с человеком. Это ровно тезис §19 доклада — точность выше точности эталона проверить нечем.

## 8. Устройство ноутбука

Тринадцать шагов, каждый заканчивается картинкой. Сверху одна ячейка с крутилками — участник меняет только её.

1. Что за задача и зачем — текст и одна иллюстрация
2. Загрузка данных в одну строку → галерея примеров по классам
3. Распределение классов столбиками → «вот он, перекос»
4. Разбиение выборки по источнику, а не случайно → почему иначе метрика завышена
5. Аугментации → сетка из 21 варианта одного снимка (прямая цитата рисунка 7 доклада)
6. Модель: бэкбон и голова, схема
7. Обучение с кривыми в реальном времени
8. Матрица ошибок и таблица точности по классам
9. Галерея самых уверенных ошибок → «на чём модель уверенно врёт»
10. Grad-CAM → куда сеть смотрит (§4 доклада)
11. Карта эмбеддингов t-SNE → §10 и рисунок 1 доклада
12. Предсказание на тесте → `submission.csv` → лидерборд A
13. Цикл детекция → сегментация → трекинг → подсчёт на ролике → лидерборд B

## 9. Хронометраж, 90 минут

| Минуты | Что происходит |
|---|---|
| 0–10 | вход на платформу, открыть ноутбук, Run All, **первый сабмит есть у всех** |
| 10–30 | данные, галерея, перекос классов, аугментации → второй сабмит |
| 30–50 | обучение, кривые, матрица ошибок, разбор ошибок, Grad-CAM |
| 50–75 | цикл детекция → сегментация → трекинг, крутилки порогов, лидерборд B |
| 75–90 | разбор лидербордов: что дало прирост и почему, перенос на свои задачи |

## 10. Риски

| Риск | Вероятность | Что делать |
|---|---|---|
| Codenrock не даст бесплатный доступ вовремя | средняя | запасной путь: HF Space под лидерборд + Colab/DataSphere под ноутбук |
| Wi-Fi на площадке не тянет 30 человек | средняя | датасет 30 МБ и веса 6 МБ уже лежат на платформе, скачивать наружу нечего |
| Участник ломает ноутбук правкой кода | высокая | все ручки вынесены в одну верхнюю ячейку; кнопка «сбросить к исходному» |
| Лидерборд насыщается, спред пропадает | средняя | три доработки из §5 |
| Вау-блок не заводится на CPU за приемлемое время | средняя | брать самые лёгкие веса (SAM 2 tiny, Depth Anything v2 small), картинку ужимать до 512 px; замерить заранее |
| VLM-кнопка требует внешнего API | средняя | либо убрать её, либо один ключ организатора на всех с ограничением числа запросов |
