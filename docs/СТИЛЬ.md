# Правила ведения документов

Действуют для всех текстов проекта: документы в `docs/`, пояснительные ячейки ноутбука, сообщения коммитов, тексты, которые увидит слушатель или заказчик.

Основа перенесена из правил доклада: `sfu-presentation/docs/СТИЛЬ.md`. Здесь она дополнена тем, что относится к практическому занятию и к коду.

## Кто читает

Научные и прикладные специалисты вне компьютерного зрения. Термин им незнаком, логика рассуждения знакома. Опыта программирования не предполагается.

Отсюда два следствия. Любой термин раскрывается при первом появлении. Любое утверждение подкрепляется числом или конкретным условием.

## Тон

Строгий технический язык норматива: сухо, по делу, констатирующий. Без оценочных и рекламных формулировок.

Лучше не написать, чем написать воду. Каждое предложение несёт факт, ограничение или вывод.

Не нанизывать парные обороты ради ритма: не только и но и, как так и, с одной стороны и с другой. Не давать обобщений ради объёма. Короткие утверждения, один факт на предложение.

Запрещённые конструкции: обеспечивает надёжную работу, гарантирует высокое качество, гибко настраивается, позволяет эффективно решать, открывает широкие возможности, играет важную роль.

## Пунктуация и оформление

| Правило | Как |
| --- | --- |
| Тире | только по правилам, не как приём. Парные вставные тире не использовать |
| Точка с запятой | внутри абзаца не применять. Ставить точку, следующее слово с заглавной |
| Стрелки-связки | не использовать. Последовательность описывать словами, таблицей или нумерованным списком |
| Жирное выделение | только заголовки и шапки таблиц, в тексте не применять |
| Кавычки-ёлочки вокруг расхожих выражений | не ставить, переформулировать |
| Перечисления длиннее трёх пунктов | таблицей |
| Таблицы | простые, шапка одна строка, без объединённых ячеек |
| Дробные числа | с запятой: 2,76 м, 0,5 м/с |
| Число и единица | через пробел: 601 МБ, 40 кадров |
| Единицы | метрические |

Длинные предложения с несколькими вставками разбивать на короткие.

## Ввод терминов

Бесшовно, по тексту, без отдельного словаря. Каждый специальный термин поясняется при первом упоминании прямо в основном тексте: коротко, скобкой или короткой фразой, не разрывая мысль абзаца. Определение даётся один раз, дальше термин используется как введённый.

Все сокращения расшифровывать при первом употреблении.

Цель: неподготовленный читатель понимает текст по ходу чтения, без словаря и без листания назад.

Сегментация допустима как устоявшийся термин.

Названия программных продуктов, библиотек и моделей на латинице в основной текст не выносить. Метод описывается по выполняемой функции: модель, принимающая текстовый запрос, а не название семейства.

## Где название модели всё-таки нужно

Организатору знать состав обязательно, иначе стенд не воспроизвести. Правило такое: в основном тексте названий нет, в конце документа отдельный раздел «Состав и происхождение» с таблицей. Раздел помечается как служебный, на занятии не звучит.

## Пояснительные ячейки ноутбука

Дополнительно к общим правилам.

| Правило | Как |
| --- | --- |
| Длина | до восьми строк на ячейку. Длиннее читатель пропускает |
| Начало | что делает ячейка, одной фразой |
| Далее | что участник увидит и на что смотреть |
| Ожидание | если расчёт дольше пяти секунд, предупредить и назвать время |
| Настройки | называть по имени из ячейки настроек, а не описательно |
| Оговорка | если результат может ввести в заблуждение, сказать об этом прямо в ячейке |

Ячейка не должна требовать от участника догадки, зачем она нужна. Если раздел не отвечает на вопрос, зачем он в занятии, раздел убирается.

## Числа

Любое число прослеживается до замера. Если замера нет, числа в тексте нет.

Числа, полученные в этом проекте, хранятся в [00-research-stand.md](00-research-stand.md) и [20-notebook-logic.md](20-notebook-logic.md). При изменении расчётов числа обновляются в обоих местах.

Не завышать статус работ. Проверенное на одной записи называть проверкой на одной записи. Прототип называть прототипом.

## Структура блока с примером

Порядок обязательный. Сначала задача, потом иллюстрация.

1. Что за производство и что контролируем.
2. Что нужно получить на выходе.
3. Каким методом решается.
4. Результат одной строкой.
5. Рисунок с подписью.

Пример без постановки задачи не годится: читатель видит картинку и не понимает, на что смотреть.

## Оговорки

Каждый документ, описывающий результат, содержит раздел с ограничениями. Правило простое: если умолчание может создать у читателя завышенное представление, оговорка обязательна.

Три случая, встречающиеся постоянно.

Показатель достиг предела не потому, что решение хорошее, а потому, что задача лёгкая. Пишем прямо, называем причину.

Величина получена приближённо. Называем, какое допущение сделано.

Сравнение идёт не с человеком, а с машинным эталоном. Называем это явно.

## Сообщения коммитов

Первая строка: что сделано, до 70 знаков, без точки в конце.

Далее пустая строка и пояснение по тем же правилам: сухо, с числами, без рекламы. Если изменение исправляет ошибку, называется сама ошибка, а не только исправление.

## Проверка перед сдачей

1. Каждый термин раскрыт при первом появлении.
2. Каждое число прослеживается до замера.
3. Нет жирного выделения в тексте, нет стрелок, нет точек с запятой внутри абзацев.
4. Перечисления длиннее трёх пунктов оформлены таблицей.
5. Названия моделей и библиотек вынесены в служебный раздел.
6. Есть раздел с оговорками.
7. Дробные числа с запятой, единицы через пробел.
